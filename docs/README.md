# Documentation guide

Start with the document that matches what you are trying to understand.

| Document | Read it when you want to… |
| --- | --- |
| [HOW-IT-WORKS.md](./HOW-IT-WORKS.md) | Follow the user journey and the internal research workflow from input to report |
| [ARCHITECTURE.md](./ARCHITECTURE.md) | See the system boundaries, graph topology, data flow, and trust controls |
| [REPO-MAP.md](./REPO-MAP.md) | Find a folder or file and understand why it exists |
| [CURRENT-IMPLEMENTATION.md](./CURRENT-IMPLEMENTATION.md) | Understand the accepted scope, runtime contracts, failure policy, cost bounds, and known limits |
| [ASSIGNMENT-COVERAGE.md](./ASSIGNMENT-COVERAGE.md) | Trace every assignment requirement and submission deliverable to repository evidence |
| [DEVELOPMENT.md](./DEVELOPMENT.md) | Set up the project, make a safe change, and verify it |
| [DEPLOYMENT.md](./DEPLOYMENT.md) | Understand the live Vercel project, production configuration, domain, and safeguards |
| [PROMPTS.md](./PROMPTS.md) | Understand which model call owns each judgment task |
| [SUBMISSION-NOTE.md](./SUBMISSION-NOTE.md) | Read the required half-page architecture and build note |
| [SAMPLE-REPORT.md](./SAMPLE-REPORT.md) | Inspect the required real generated report artifact |

The project is deliberately a focused Level 1 take-home, not a general account-monitoring platform. When a document describes a future improvement, it labels it as future work rather than current behavior.
