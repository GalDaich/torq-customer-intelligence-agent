## Presentation and final live-acceptance checklist

Before presenting or describing the project as fully acceptance-tested:

- run an unprepared company through the UI;
- let a non-technical person drive input, confirmation, and report reading;
- verify ambiguous, manual website, discard, and restore behavior;
- verify a five-company batch and independent UUIDs/traces;
- verify weak-public-data and deliberate partial-provider-failure behavior;
- audit every rendered source link and duplicate job/technology behavior;
- confirm the matching identity-normalization and graph traces in LangSmith;
- rehearse a small report-field change and the affected schema -> prompt -> grounding -> UI path;
- review the current dependency advisory report before final submission or longer-lived public operation.

The included HiBob report proves one real successful run. It does not prove these remaining scenarios.
